# ADR 012 · Datos desactualizados de las heladeras

Fecha: 2020-11-19

## Estado

Propuesto

## Contexto

El sistema de heladeras inteligentes es un sistema externo que provee información vital para el cliente y para el *sistema de órdenes*. Pero no controlamos la frecuencia de actualizaciones, la estructura de datos ni la gestión de las posiciones disponibles. Aun así, tenemos que proveer nuestro servicio basándonos en los datos provistos y tratar de mantener el inventario de nuestro lado lo más preciso posible, para evitar colisiones y situaciones donde el usuario pueda quedar insatisfecho con nuestro servicio.

Existe el riesgo de que en algún momento no podamos obtener datos actuales (offline, mantenimiento, throttling, caché, etc). ¿Cómo va a manejar esas situaciones el sistema de órdenes?

El usuario ocasional (que paga en efectivo) es un factor principal en este problema. Las comidas pre-pagadas que aún pueden retirarse en un escenario offline no contribuyen realmente al problema de datos obsoletos, porque el servidor de pagos ya hizo su trabajo.

## Decisión

Vamos a cachear y mantener la integridad de los datos sobre el stock disponible en las heladeras de nuestro lado, hasta que recibamos datos nuevos del *sistema de heladeras inteligentes*, momento en el cual los datos se ajustarán.

## Consecuencias

Almacenar datos sobre el stock disponible agrega presión computacional a nuestro sistema y complejidad cognitiva al modelo de concurrencia del sistema para la integridad de datos. Aceptamos estas consecuencias porque podemos operar con los stocks estimados y proveer nuestro servicio a los usuarios finales. Esta decisión impacta el proceso de compra y requiere una decisión de negocio sobre el caso borde cuando algo se compró pero no se entregó.

Debería haber un sistema de monitoreo y alertas para el sistema de *heladeras inteligentes*. El equipo debe ser informado a tiempo cuando un faltante de datos supere el hueco definido.

Debería involucrarse un patrón ping si los sistemas de *Smart Fridges* no tienen otros manejadores de health-check.

**Riesgos:**

- Pérdidas por compensación con cupones al cliente

**Acciones**

- Definir con el negocio y el equipo técnico cuándo lanzar una alarma ante un hueco de datos. Puede ser en minutos u horas, por ejemplo.
