# ADR 008 · Entrega "al menos una vez" para la orden lista a pagar

Fecha: 2020-11-01

## Estado

Propuesto

## Contexto

Las órdenes "listas para pagar" deben tratarse con cuidado especial. Queremos garantizar "entrega al menos una vez" para cada orden. El procesamiento del pago de una orden es un escenario crítico del negocio, porque vender comidas es el punto entero. En este caso debe haber una garantía de que el store de órdenes y el procesador de pagos pueden tomar la orden para ejecutarla.

Al mismo tiempo, es muy importante evitar pagos dobles por problemas de concurrencia. Cuando llega una orden en estado "lista a pagar", en teoría puede procesarse una o más veces, pero no debería llevar a cargos dobles, triples, etc. de la cuenta del usuario.

## Decisión

La entrega de órdenes "listas a pagar" se realiza con un software de MessageQueue con opción de acuse de recibo. Además, esperamos que la orden llegue con un identificador único desde los dispositivos del cliente al momento del procesamiento. Durante el procesamiento de la orden, se puede chequear la existencia de una orden con el mismo id, y el número de versión debe usarse para validar obsolescencia. En este caso, el evento con la misma versión va a ser descartado por el servicio que procesa.

## Consecuencias

Va a disminuir levemente la performance, pero obtenemos integridad de datos. El uso de EventStore y proyecciones con el estado de la orden va a ayudar a manejar cambios de estado correctos para las órdenes.
