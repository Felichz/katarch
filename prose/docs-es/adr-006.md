# ADR 006 · Arquitectura zero trust

Fecha: 2020-10-30

## Estado

Propuesto

## Contexto

El _sistema de órdenes_ se comunica con sistemas aguas arriba y aguas abajo en un entorno de nube, y no podemos confiar en el supuesto de que los pedidos de la misma subred son seguros.

El _sistema de órdenes_ está implementado como un monolito modularizado y esos módulos eventualmente se extraerán para volverse servicios dedicados. Tenemos que asegurar esas llamadas desde una etapa temprana para facilitar la migración de módulo a servicio.

## Decisión

Las llamadas internas entre módulos deben incluir información de seguridad con datos de auth y claims desde el principio.

## Consecuencias

Aplicar este enfoque agrega complejidad a la comunicación entre módulos dentro del mismo dominio. Puede no ser obvio para muchos desarrolladores. A cambio, permite una separación adecuada de la comunicación entre módulos y preparación para extraer módulos como servicios.

El enfoque sugerido va a requerir involucrar un servicio de identidades y aumentar la complejidad de la lógica interna dentro de los servicios monolíticos, pero simplifica el escalamiento futuro con servicios dedicados.

Se va a requerir alguna optimización dentro de los módulos monolíticos cuando los módulos se incorporen.
