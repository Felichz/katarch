# ADR 002 · Enfoque del sistema

Fecha: 2020-10-29

## Estado

Aceptado

## Contexto

Tenemos que decidir cuál va a ser el enfoque dominante del sistema. Hay varias opciones: monolito, microservicios, micro-kernels, blackboard.

También existen restricciones técnicas y drivers de negocio; aun si el cielo es azul y la elección es libre, la experiencia y las capacidades del equipo de desarrollo deben ser consideradas.

### Alternativas

Mapa de valores:

- **+** Promueve
- **++** Promueve fuertemente
- **O** Neutral
- **-** Negativo
- **--** Negativo fuertemente

| | Monolito | Microservicios | Micro-kernel | Monolito modularizado |
|----|----|----|-----|-----|
| Facilidad de despliegue  | ++ | -  | -  | ++ |
| Disponibilidad        | -  | ++ | +  | - |
| Autonomía          | -- | ++ | ++ | + |
| Trazabilidad        | ++ | -  | +  | O |
| Performance         | ++ | +  | +  | ++ |
| Modificabilidad        | O  | ++ | +  | + |
| Mantenibilidad      | -  | ++ | +  | + |
| Integridad           | ++ | -- | O  | + |
| Seguridad            | -  | ++ | +  | ++ |
| Escalabilidad         | -- | ++ | -  | + |

## Decisión

Basándonos en las alternativas, en el contexto de las necesidades del negocio y del equipo de desarrollo, pensamos que el monolito modularizado es la mejor opción por ahora. Al mismo tiempo, abre la posibilidad de migrar a microservicios cuando sea necesario.

## Consecuencias

Los beneficios principales aparecen en el área de desarrollo y despliegue. El equipo puede ahorrar muchos recursos armando los ambientes dev/test/qa/prod. El costo de desarrollo y la complejidad cognitiva son bajos, porque trabajar sobre la misma base de código requiere menos reuniones de sincronización.

La extensibilidad y modificabilidad con el enfoque propuesto deberían quedar en un nivel alto con fachadas bien diseñadas entre módulos.

Se debe aplicar cuidado y disciplina extra en la comunicación entre módulos, o será solo un monolito con tendencia hacia "la gran bola de lodo". Cada módulo debe mantener limpios los conceptos de su subdominio y a veces copiar y pegar una parte del código es el mejor enfoque para evitar dependencias ocultas.
