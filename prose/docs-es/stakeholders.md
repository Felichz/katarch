# Stakeholders

Lista de todos los stakeholders del _sistema de órdenes_

| Stakeholder | Intereses |
|----|--------|
| Ghost Kitchen | Obtener información sobre el consumo de comidas preparadas y entregadas para prever la reposición de insumos |
| | Obtener información sobre pedidos bajo demanda |
| Suscriptores | Armar un menú y recibir las comidas a tiempo |
| | Recibir notificación de llegada o demora de la comida para ahorrar tiempo |
| | Estar informados sobre los ingredientes de las comidas |
| Usuarios conocidos | Explorar el catálogo y comprar con garantía de encontrarla cuando vengan a retirarla |
| | Facilidad del proceso de compra |
| | Estar informados sobre los ingredientes de las comidas |
| Usuarios ocasionales | Elegir una comida visualmente, obtener información y pagar de la manera más conveniente al mismo tiempo |
| Dueño | Atraer a todos los tipos de usuario |
| | Mejorar la calidad de la comida y del servicio |
| | Información sobre las preferencias de los usuarios |
| | Soporte para el sistema de contabilidad |
| Nutricionistas | Buscar en el catálogo por componentes específicos |
| | Cálculo de % de grasas\carbohidratos\vitaminas\... |
| Desarrolladores | Facilidad de mantenimiento y desarrollo del sistema |
| Administradores | Facilidad de monitoreo |
| | Facilidad de configuración y escalado |
| Proveedores de comida | Plan de compras y entregas previsible |
| Cocinas de terceros | Igual que para la Ghost Kitchen |
| Administradores de PoS | En la app solo deben verse las comidas de las heladeras instaladas localmente |
| | Acceso fácil a ingredientes y alérgenos de cada comida |
| | Facilidad para registrar la operación de venta |
| | Generación automática de reportes de actividad de ventas |
